# innocent world レンガ村の物語　追加機能の設計案

状態：**承認済み・実装済み（v1）**

- 物語本文は GAS から配信する方式を採用
- Googleサイトは埋め込み・全画面の両方に対応（基本は全画面を推奨。実機テスト後に最終決定）
- 準備手順：docs/gas-setup.md　シナリオの書き方：docs/scenario-sheets.md

## 1. 全体の構成

```
入口のQRコード
   │
   ▼
Googleサイト（来場者向けの表示画面）
   │  ├─ 説明・お知らせ・地図の案内
   │  └─ 「レンガ村へ入る」…GitHub Pages の物語アプリ（埋め込み、または全画面で開く）
   ▼
物語アプリ（GitHub Pages：story/ フォルダに追加）
   │  住民登録 → 入口のことば → 村の地図 → 施設のことば → 物語 → エンディング
   │                                                          │
   │  fetch（HTTPS）                                         ▼
   ▼                                                   ARは別画面（新しいタブ）で開く
Google Apps Script（GAS：Webアプリとして公開）           既存のARパレード・花火・クリスマスは変更なし
   │  住民票の発行・照合／ことばの正解判定／物語本文の配信／記録の保存
   ▼
Googleスプレッドシート（運営者だけが見られる）
   住民・参加履歴・解放記録・進行・選択結果・ことば・物語本文・集計

スマートフォン（localStorage）：住民番号と合言葉、進み具合の控え、未送信の記録
```

### 既存アプリへの追加のしかた（安全のため）

- 物語の機能は、新しいフォルダ `story/` に別ファイルとして作ります。
- 既存の `index.html` への変更は、次の2点だけにします。ARパレード・花火・クリスマス・ハロウィンの中身には手を入れません。
  1. 物語アプリから、表示するARを選んだ状態で開けるようにする（例：`?ar=xmas`）
  2. 最初の画面に「レンガ村の物語」への入口を1つ足す（不要なら足しません）
- 物語アプリは `story/index.html` という別ページにします。Googleサイトへの埋め込みや入口QRは、このページを指します。

## 2. Googleサイトへの埋め込みで起きる制約と対策

Googleサイトの「埋め込み」は、別のドメインの枠（iframe）の中でページを表示します。このため、次の制約が出ます。

| 項目 | 埋め込みの中 | 対策 |
|---|---|---|
| カメラ（AR） | 使えない見込み（埋め込み枠にカメラの許可を付けられない） | **ARは新しいタブで開く**。物語のエンディングの「ARを見る」ボタンで、GitHub Pages のAR画面を開く |
| 傾きセンサー（iPhone） | 許可を求められない見込み | 同上 |
| 全画面表示 | 使えない | 同上 |
| スマホ内の保存（localStorage） | 使えるが、**Googleサイトの中と、直接開いたときで別々に保存される**（Safari・Chrome の仕様） | 正式な記録はスプレッドシートに置き、スマホ側は控えにする。どちらで開いても、住民番号と合言葉で同じ記録を読み込める |
| Safari の保存期間 | 7日間そのサイトを使わないと、スマホ内の保存が消えることがある | 次回イベントの再訪判定は**スプレッドシート側で行う**。住民票の「復元コード」でいつでも戻せる |
| 画面の高さ | 埋め込み枠の高さが固定され、スマホでは窮屈になりやすい | 物語アプリは縦長の枠でも崩れない作りにする。体験しやすさを優先するなら、埋め込みではなく「全画面で開く」ボタンにする方法も用意する |

※ 実際の挙動は、Googleサイトに試験ページを作り、iPhone と Android で確認してから確定します。

**おすすめ**：Googleサイトには、説明と「レンガ村へ入る」ボタンを置きます。物語アプリは、埋め込みでも全画面でも動くように作ります。会場でのテストで操作しやすいほうを選んでください。

## 3. 認証のしくみ（匿名で参加）

個人情報は集めません。メールアドレス・電話番号・本名は使いません。

### 住民登録

1. 来場者がニックネームなどを入力します。項目は芽美の設計で決めます。
2. GAS が次の3つを発行します。
   - **住民番号**（例：`RV-4821-37`）：住民票に表示します。
   - **合言葉（トークン）**：長いランダムな文字列で、スマホに保存し、通信のたびに送ります。
   - **復元コード**（例：`KX7P-29QM-H4TA`）：住民票に表示します。機種変更のときに使います。
3. スプレッドシートには、合言葉と復元コードを**そのままでは保存せず、ハッシュ（元に戻せない形）にして保存**します。

### 機種変更・保存が消えたとき

- 住民票の「復元コード」を新しいスマホで入力すると、住民票・もちもの・進み具合が戻ります。
- 住民票の画面で、スクリーンショットで復元コードを残すよう案内します。
- 復元するたびに合言葉を作り直し、古いスマホからは使えなくします。

### ひみつのことば

- 正解の判定はすべて GAS で行います。**正解のことばは GitHub Pages の公開コードに含めません。**
- 正解のことばはスプレッドシートの「ことば」シートで管理し、開催日ごと・施設ごとに変えられます。
- 「今日」の判定は、スマホの時計ではなく**サーバー側の日本時間**で行います。
- **総当たり対策**：同じ住民が同じ施設で何度も間違えたら、数分待ってもらいます。
- 一度解放した施設は、その日のあいだは再入力なしで読めます。解放の記録はスプレッドシートとスマホの両方に残します。
- 翌日は再入力が必要です。前日までの選択・もちもの・進み具合はそのまま残ります。

### 物語本文のネタばれ対策（おすすめ）

正解のことばを隠しても、物語の本文が公開コードにあると、詳しい人は先に読めてしまいます。そこで、**物語の本文も GAS から配信**します。施設のことばに正解したときだけ、その施設の物語が届く形です。

- 本文はスプレッドシートの「物語」シートに、1行1セリフで書けます。芽美の設計をそのまま貼り付けられる形にします。

### 限界

イベント体験用の簡易認証です。厳密な本人確認や、現地にいることの証明にはなりません。ことばを会場の外で教え合えば、会場にいなくても解放できます。

## 4. スプレッドシートの構成

| シート | 主な列 | 用途 |
|---|---|---|
| 住民 | 住民番号, 合言葉ハッシュ, 復元コードハッシュ, ニックネーム, なかよしの住人, 好きな色, 登録日時, 最終来訪日時 | 住民票 |
| 参加履歴 | 住民番号, イベントID, 開催日, 最初の入場時刻 | 再訪判定・参加者数 |
| 解放記録 | 住民番号, 開催日, 施設ID（入口は `entrance`）, 解放時刻 | その日の解放状態・施設の訪問状況 |
| 進行 | 住民番号, 施設ID, 物語ID, 状態（読んだ／読み終えた）, 日時 | 物語の進行状況 |
| 選択 | 住民番号, 開催日, 場面ID, 選択肢ID, 選択肢の文, 日時 | 選択結果の集計 |
| 状態 | 住民番号, もちもの・ポイント・記録（JSON）, 更新日時 | 復元用のまとめ |
| 開催日 | イベントID, 開催日, 表示名（1日目など） | 継続開催の管理 |
| ことば | 開催日, 施設ID, 正解（複数可） | ひみつのことば |
| 施設 | 施設ID, 名前, 地図上の位置, 表示条件 | 地図 |
| 物語 | 場面ID, 順番, 話す住人, セリフ / 選択肢, 次の場面, もらえるもの, 条件 | 物語本文 |
| 集計 | （自動計算） | 登録者数、日別の参加者数、再訪者数、施設ごとの訪問数、選択肢ごとの人数 |

- 「次回イベントでの再訪」は、**参加履歴に前のイベントIDがあるか**で判定します。2日目の再訪も、前回イベントからの再訪も、同じしくみで判定できます。
- 集計シートは、スプレッドシートの関数で自動更新します。運営者だけが見られます。

## 5. 通信の流れとスマホ側の保存

| 操作 | スマホ → GAS | GAS → スマホ |
|---|---|---|
| 住民登録 | ニックネームなど | 住民番号・合言葉・復元コード |
| 起動時 | 住民番号・合言葉 | 今日の開催情報、解放済みの施設、進み具合、再訪かどうか |
| 入口のことば | ことば | 正解かどうか、今日の地図 |
| 施設のことば | 施設ID・ことば | 正解かどうか、その施設の物語本文 |
| 選択・読了 | 場面ID・選択肢など（まとめて送信） | 受け付けました |
| 復元 | 復元コード | 新しい合言葉と、すべての記録 |

- スマホ側の保存（localStorage）：住民番号・合言葉、今日解放した施設と受け取った物語本文、進み具合の控え、未送信の記録。
- **電波が弱いとき**：選択や読了の記録はスマホに貯めておき、つながったときにまとめて送ります。物語は止まりません。
- ことばの判定と住民登録だけは、通信が必要です。会場の通信環境（Wi-Fi など）の確認をおすすめします。

## 6. 無料枠と制約（Google Apps Script・スプレッドシート）

| 項目 | 制約 | この設計での対応 |
|---|---|---|
| 同時に動ける数 | GAS は1つのアカウントで**同時30件まで**（一般の Gmail アカウント） | 通信をまとめて回数を減らす。混んだときは少し待って自動で再送する |
| 1回の処理時間 | 最大6分 | 1回の処理は1秒前後で終わる作りにする |
| 応答の速さ | 1回あたり1〜3秒ほどかかることがある | 待っている間はアニメーションを出す。物語本文はまとめて受け取る |
| 書き込みの衝突 | 同時に書くと行がずれることがある | GAS の排他制御（LockService）で順番に書き込む |
| スプレッドシートの容量 | 1ファイル1,000万セルまで | 数千人規模の数年分でも余裕がある見込み。大きくなったらイベントごとに別ファイルへ分ける |
| 公開範囲 | GAS は「自分として実行・誰でもアクセス可」で公開する | スプレッドシート自体は公開しない。GAS が返すのは本人の記録だけ |

※ 同時30件の上限は、入口で数百人が一斉に登録するような場面で効いてきます。事前に負荷テスト（同時アクセスの試験）を行います。

## 7. 個人情報の扱い

- 集めるもの：ニックネームと、遊びのための選択（好きな色・なかよしの住人など）。本名・連絡先は集めません。
- 登録画面に、短い説明を表示します。例：「記録は innocent world の運営と、物語の集計だけに使います」。
- 子どもが参加することも想定し、ニックネームに本名を入れないよう案内します。
- 住民票の削除（記録を消す）ボタンを用意します。

## 8. 実装の順番（合意後）

1. スプレッドシートの雛形と GAS のAPI（住民登録・起動・ことば判定・記録・復元）を作ります。
2. `story/` の物語アプリを作ります（住民票、入口のことば、地図、施設のことば、物語、エンディング → ARを新しいタブで開く）。
3. 既存アプリに `?ar=` を追加します（ARを選んだ状態で開く）。
4. Googleサイトの試験ページで、埋め込みの挙動を iPhone と Android で確認します。
5. 芽美の物語を「物語」シートに入れ、通しで試遊します。
6. 負荷テストをして、入口QRコードを作ります。

### GASのデプロイについて

GAS はお客さまの Google アカウントで作る必要があります。私がコード一式（GAS のスクリプトと、スプレッドシートの雛形）を用意します。貼り付けと公開の手順は画面つきでご案内します。
