innocent world｜レンガ村の物語・確定ルール v1.1

記録日：2026年10月18日
目的：今後のシナリオ制作・Claudeへの実装依頼で仕様が曖昧にならないようにするための基準文書。

1. 世界観・主人公

• ブランド名：innocent world。タグライン：ここは、やさしさでできた世界。
• 舞台：絵本の門の向こうにあるレンガ村。門そのものの名前ではない。
• 主人公は住民登録をした来場者本人。物語中では登録ニックネームを使う。
• エスパーは主人公の代役ではなく、登場人物の一人。来場者の冒険を導く少年として扱う。
• 住人は10人：エスパー（esper）、ミミ（mimi）、リリィ（lily）、ルーク（luke）、ニコ（niko）、ハル（hal）、アリカ（arika）、ヌール（nuru）、モック（mock）、じいじ（jiiji）。
• ヌールの表示名は「ヌール」、英語表記は「NOUR」。既存ARとの互換性のため内部IDは nuru を維持。シナリオ上の nour も同一人物として解釈される（Claude報告）。

2. 入場・施設解放

• QRコードはイベント入口の1か所のみ。入口QRからGoogleサイトへ誘導する。
• 各施設にはQRコードを設置しない。アプリの地図から施設を選び、現地看板にある**「ひみつのことば」**を入力する。
• 当日の入口のことばを入力してから、その日の物語・地図が解放される。
• 施設ごと・開催日ごとに別のことばを設定。正解するとその施設の当日の場面が解放され、同じ日は再入力不要。
• 2日目は新しい入口・施設のことばが必要。前日までの選択・アイテム・進行記録は引き継ぐ。
• ことばの正解判定はGAS側。開催日の判定はサーバー側の日本時間。公開GitHubコードには本番の正解を含めない。
• ひみつのことばは会場外で共有され得るため、厳密な現地滞在証明にはならない。

3. システム構成と運用

• Googleサイト：入口QRの遷移先・案内サイト。物語アプリを埋め込むか全画面で開くかは実機テストで決定（両対応）。
• GitHub Pages：物語Webアプリ story/、既存ARアプリ。既存のパレード・花火・クリスマス・ハロウィンの内容・デザインを維持。
• Google Apps Script（GAS）：住民登録、認証、ことば照合、物語配信、記録処理。
• Googleスプレッドシート：住民・参加履歴・解放・進行・選択・物語・ことば・集計の正式データ。
• localStorage：端末側の控え・未送信記録。端末変更やブラウザ保存削除に備え、正式記録はスプレッドシートに置く。
• エンディングからARへ移る際は、カメラ・センサー制限に備えて別画面で既存ARを開く。
• 物語本文・選択肢・分岐・アイテム・エンディングはスプレッドシートで管理し、GAS経由で必要な場面だけ配信する。
• 住民登録は匿名・ニックネーム中心。本名・メール・電話番号は原則収集しない。住民番号・認証トークン・復元コードは別用途として区別する。
• 事前住民登録は可能にする方針。ただし物語開始には当日の入口のことばが必要。

4. シナリオ差し込み文字

Claude報告に基づく実装仕様：

• {name} または {住民名} → 登録した住民名（ニックネーム）
• {color} → 登録した好きな色
• {friend} → 登録した「いちばん会いたい住人」の名前
• 使用できる欄：セリフ／選択肢の文／ARボタンの文字／ひみつのことば正解時のメッセージ。
• 認識できない {…} は置換されず、そのまま表示される。試遊時に確認する。
• 選択結果の集計は置換前の選択肢文で記録され、住民名の違いで集計が分裂しない。
• {friend} は表示名の差し込みであり、選んだ住人による会話分岐とは別の仕組み。

5. シナリオデータ形式

• Claude指定の docs/scenario-sheets.md に準拠する。
• シート区分：イベント／開催日／ことば／施設／物語の入口／場面／セリフ／選択肢／アイテム／ポイント／住人／登録項目、および記録・集計用シート。
• IDは半角英数字とアンダースコア（例：well_01）。イベントごとに固有の event_id を付与。
• 登場人物IDは原則 esper, mimi, lily, luke, niko, hal, arika, nuru, mock, jiiji。
• 公開期間・開催日・条件・選択肢分岐・アイテム・ポイント・AR種別はスプレッドシートで設定。
• 実際の開催日は未確定。2026年12月19〜20日や iw2026xmas はClaudeの書式例であり、本番日程・イベントIDの確定値ではない。

再訪判定条件（2026年10月18日追加）

• 今回再訪：同一イベントの前の開催日にも参加した住民。両日参加者向けの専用場面に使う。
• 再訪：以前の開催日に参加したことがある住民。別イベントの参加履歴も含むため、両日参加の判定には単独で使わない。
• 前回参加：別のイベント（前回の innocent world）への参加歴がある住民。
• 2日目；初来訪：開催2日目が初めての来訪である住民向けの導入条件。前回イベント参加者が今回2日目に初参加する場合の挙動は、Claude側の条件定義・実装で要確認。
• 今回再訪 のローカル試験は報告済み。前回イベントのみ参加した住民が 今回再訪 に該当しないことの境界テストは未実施。

6. 物語制作方針（現時点の合意）

• 1日目の題名：『最後のページがない絵本』。1日だけの参加でも物語を完結させる。
• 2日目の仮題：『絵本に書かれていない物語』。両日参加者には再訪者ならではの展開を用意し、2日目のみの来場者にも理解できる導入を設ける。
• 各施設の手がかりが最後に結びつく構成。単なるスタンプラリーにしない。
• 子どもには冒険、大人には余韻の残るテーマ。結末は来場者の選択を尊重する。
• 村長（じいじ）が最後のページを破った理由は、村人に帰還を強いる約束から解放したいという葛藤に由来する、という既存の物語案を基礎にする。ただし詳細な筋・セリフ・分岐・施設ごとの正解のことばは制作中で未確定。
• 物語の想定所要時間は1日目30〜40分、2日目20〜30分の提案値であり確定ではない。
