# 物語の導入と帰還（設計）

状態：**仕様確定・未実装**（公開アプリ・本番DBへの反映は別途承認後）　最終更新：2026-10-20

## 0. 確定した仕様（2026-10-20）

1. **ひみつの言葉は絵本の留め金に組み込む。** 正しい言葉で留め金が外れ、絵本が開く。言葉で作品が決まる仕様はそのまま（同じ日に複数作品があっても、言葉に対応する作品の絵本が開く）。
   - まちがい：留め金がカチャカチャと揺れるだけ（今の「ことばがちがうみたい」の案内はそのまま）
   - 開始前・終了後：今の案内（「○時からはじまります」「今日はおしまい」）を部屋の画面で出す
   - 作品を切りかえるときは、地図の「絵本をとじる」→ 部屋 → 別の言葉で留め金を外す
2. **物語は部屋への帰還で終わる。** 冒頭と同じ部屋・同じ視点・同じ家具配置。作品ごとの記念の品を机の上に表示。帰還後は余韻を優先し、地図へのボタンは小さく目立たないものにする。
3. **導入の文章・現れる住人・訪ねてきた理由は、作品ごとに制作シートで設定する。** 共通にするのは「部屋で絵本を読む → 住人が現れる → 一緒に絵本の世界へ入る」までの映像演出だけ。
4. **冒頭の部屋は夜。** ベッドに入る前に絵本を読んでいる。窓の外に月と星、机にランプ。帰還も同じ部屋。
5. **今の物語の内容は勝手に変えない。** 文を直す必要があるところは、芽美への依頼として報告する。

## 1. 基本の流れ（すべての物語で共通）

```
自分の部屋（夜・カーテンは閉じている・机に「innocent world」の絵本）
  ↓ 絵本をひらく（参加者の操作は「読む」だけ）
ページがめくれる → 絵本の中から登場人物が現れる → 部屋での会話
  ↓ 登場人物といっしょに、絵本の世界へ（光に包まれる）
レンガ村に到着（どの物語でも必ずここに着く）
  ↓ 作品の本編（intro → 地図 → 冒険）
光に包まれる → 冒頭と同じ部屋・同じ構図に戻る → 机の上に作品ごとの記念の品
```

- 『エスパードリーム』から引き継ぐのは、**「部屋で絵本を読んでいると、絵本の中から登場人物が現れ、その人物と一緒に絵本の世界へ入る」という演出の形だけ**。
  「姉がさらわれた」などの固有の設定は使わない。
- 参加者が自分の意思で飛び込むのではなく、絵本を読んでいたら不思議な出来事に巻き込まれる。
- **映像の演出は共通**（アプリで作る）。**現れる人物・現れる理由・会話は作品ごと**（シートのデータで変えられる）。
- 導入は「作品×開催日」ごとに1回。2回目以降の参加者も、作品（または再公開）ごとに必ず見る。同じ日の読み込み直しや、別の作品からの戻りでは繰り返さない。

## 2. 共通の演出（アプリ側・作品によらない）

| 段 | 画面 | 演出 |
|---|---|---|
| ① 部屋 | 夜の部屋。机の上に閉じた絵本とランプ | 静かな部屋の音楽。「絵本をひらく」ボタン |
| ② ページ | 絵本が開き、ページがめくれる | めくれる音。ページの絵（レンガ村）が少し動き出す（風車・旗・光） |
| ③ 登場 | ページが光り、人物が絵本から浮かび上がって部屋に立つ | 光の粒。人物は作品データで決まる（1人でも複数でもよい） |
| ④ 会話 | 部屋で、現れた人物との会話（ふつうのセリフ画面） | 作品データのセリフ。選択肢を入れてもよい |
| ⑤ 入る | 人物が手をさしのべる → ページから光があふれ、部屋が絵本に吸いこまれる | 光とワープの音（帰還の光の演出と対になる） |
| ⑥ 到着 | レンガ村の入口 | 共通の到着の絵。ここから作品の本編へ |

帰還（物語の最後）は、⑤の逆（光が消えると部屋）→ ①と同じ構図の部屋 → 窓の外にお別れの人物 → 机の上の記念の品。

## 3. 作品データ（芽美の制作シート）

**シートの列は増やさない。** 今ある「物語の入口」「場面」「セリフ」「選択肢」の書き方で作れる。

1. 「物語の入口」に、施設ID **`prologue`** の行を足す（`intro` と同じ書き方。条件で「再訪」などの出し分けもできる）
2. 導入の場面は、次の**導入用の背景名**を使う（絵と演出はアプリが共通で用意する）

| 背景名 | 意味 | アプリの演出 |
|---|---|---|
| `room` | 部屋（絵本は閉じている） | この場面の最後に「絵本をひらく」ボタン |
| `room_book` | 絵本がひらく | 場面に入ったとき、ページがめくれる |
| `room_appear` | 絵本から人物が現れる | **この場面で最初に話す住人**（話す住人ID）が、絵本から浮かび上がる。2人目以降の話し手も順に現れる |
| `room_talk` | 現れた人物と部屋で会話 | 現れた人物が部屋に立ったまま |
| `room_enter` | いっしょに絵本の中へ | 最後のページのあとに光の演出 → レンガ村に到着 → 作品の `intro` へ自動でつながる |

3. 導入の最後の場面の「次の場面ID」は空欄でよい（**到着は必ずレンガ村**になるよう、アプリが `intro` につなぐ）
4. 作品の `intro` の最初の場面は、**到着したところから**書く（背景は到着の絵）。「門をくぐる」など、自分から入る書き方はしない
5. 帰還の場面は次の背景名を使う（冒頭と同じ部屋・同じ構図）

| 背景名 | 意味 | アプリの演出 |
|---|---|---|
| `bedroom` | 光が消えると部屋にいる | 中央広場などから移るとき、光に包まれる演出のあとに表示 |
| `bedroom_window` | 窓の外にお別れの住人 | 1行目は「こつん」の音（カーテンは閉じている）→ 2行目でカーテンが開く → 最後の行で住人が星になって消える。窓の外の住人は**この場面で話す住人**から決める |
| `bedroom_memento` | 机の上の記念の品 | **この場面の「もらえるアイテム」**を記念の品として机の上に表示（作品ごとに変えられる） |
| `bedroom_bookmark` | （『消えた最後のページ』専用）机の上の古いしおり | 今のまま。新しい作品では `bedroom_memento` を使う |

6. 最後の場面の「記録する」に `_complete` で終わる記録（例：`letter_complete`）を書くと、短い最後の行が光る文字のしめくくりになる（今のルールのまま）
7. 導入（`prologue`）がない作品は、アプリの共通の導入（エスパーが現れる短い会話）を使う
8. 導入の中では、ポイント・アイテムは渡さない（記録は書いてよい。例：`met_mimi_room`）。選択肢は `room_talk` に入れてよい
9. 本番DBに写しても、アプリが導入に対応するまでは `prologue` の行は使われない（今の動きに影響しない）

## 5. アプリの変更箇所（実装するとき）

- `story/story.js`：部屋の画面（入口・お休み・終了も部屋に）／導入の流れ（`prologue` → 共通の到着 → `intro`）／導入用の背景の演出（めくれる・現れる・入る）／窓の人物と記念の品をデータから／最後のボタン
- `story/scenes.js`・`story/art/`：部屋（帰還と共通の構図）・絵本・到着の絵（ビジュアル刷新の素材）
- `story/story.css`：ページめくり・人物が浮かび上がる・吸いこまれる演出
- `story/i18n.js`：「絵本をひらく」「絵本をとじる」など（3言語）
- `story/bgm.js`：部屋の音楽
- `gas/Code.gs`：入口の言葉が正しかったときに、`intro` に加えて `prologue` の場面も返す（小さな追加）。作品の切り替え・案Aの仕組みはそのまま使える

## 6. 必要な絵の素材（ビジュアル刷新の優先順）

1. 自分の部屋（夜。カーテンが閉じた絵／開いた絵。机・ランプ・本棚）…導入と帰還で共通

3. レンガ村に到着した場面（共通）
4. 記念の品の絵（作品ごと）
