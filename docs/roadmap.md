# innocent world 開発計画（長期方針）

最終更新：2026-10-20

## サイトの役割

| サイト | 役割 | 対象 |
|---|---|---|
| **公式サイト**（現在のARサイトを発展） | 世界観の紹介・ファン育成・情報発信・将来の商品販売。誰でも見られる | 一般・ファン |
| **レンガ村アプリ**（`story/`） | イベントの中心。現地での物語・ARパレード・ARレース・住民票 | イベント参加者 |
| **主催者用管理サイト**（`admin/`） | 開催スケジュール・ひみつのことば・運営管理 | 主催者・スタッフ |

## 方針

1. **レンガ村をイベントの中心にする**
   - 物語・ARパレード・ARレース・住民票をレンガ村から使えるようにする。
   - 物語とARイベントは別々に管理する。物語の読了をARイベントの参加条件にはしない。
2. **今のARサイトは、移植と動作確認が終わるまでそのまま動かす**
   - 移植は段階的に行い、既存の機能を壊さない。今はまだ移植を始めない。
   - 移植のあとは、誰でも見られる公式ポータルサイトにする。
     ハロウィンの部屋・クリスマスの部屋など、自宅でも楽しめる季節の無料AR体験を置き、イベントのない期間も innocent world とのつながりを保つ。
3. **公式サイトの主な内容（予定）**
   世界観の紹介／レンガ村と今後登場する村々の紹介／キャラクター・住人図鑑／上演作品の紹介／イベント開催情報・スケジュール／季節コンテンツ／自宅で楽しめる無料AR／お知らせ・新着情報／将来のオリジナルグッズ販売／将来の物語の絵本販売
   - オンラインショップは将来追加。今は決済機能を作らない。
4. **管理サイトで登録した開催情報を、公式サイトにも自動で出す**
   - サーバーの `publicSchedule`（ことばを含まない開催予定）を公式サイトが読む形にしてある。
5. **管理サイトは、将来ARパレード・ARレースの開催日時も管理できるようにする**

## 統合しやすくするための設計上の決めごと（今から守る）

- **上演スケジュールは「何を・いつ」の一般的な形にする**：今の「開催日」シートは物語用。ARイベントを足すときは、同じ考え方（作品／種類・日付・開始・終了・猶予・状態）の行を増やし、管理サイトのカレンダーに種類ごとの色で並べる。物語の条件（読了・記録）とは結びつけない。
- **住民票は共通の土台**：住民番号・トークン・復元コードの仕組みはレンガ村に1つ。ARの参加記録も、移植後は同じ住民票にひもづける（物語の進行とは別の記録として）。
- **公開してよい情報と、ひみつの情報を分ける**：公式サイトが読むのは `publicSchedule` のような公開用の出口だけ。ことば・管理者・住民の記録は出さない。
- **ARの部品は、ページから切り離して持ち運べる形にしていく**：移植の段階では、今のARサイトのコード（`index.html`）を直接動かさず、レンガ村側に写して確かめる。今のサイトは移植後の動作確認が終わるまで変更しない。
