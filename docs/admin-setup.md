# 主催者用管理サイト　準備と使い方

状態：**手元の開発環境で作成・テスト済み。本番には未反映**（本番反映は、内容を確認してから改めて指示をもらう）

- 管理サイト：`admin/`（公開後は `https://satoshikishimoto.github.io/innocentworld/admin/`）
- サーバー：物語と同じ `gas/Code.gs`（管理用の処理は `admin` で始まる action）
- 手元のテスト：`node tools/gas-emu/server.js 8790` → `node tools/gas-emu/test-admin.js 8790`（51項目）

## 1. しくみ

```
主催者のスマホ/PC ─▶ admin/（GitHub Pages。ひみつの情報は何も持たない）
     │ ① Google でログイン → ID トークン
     ▼
GAS（Code.gs） ─ ② Google に ID トークンを確かめてもらう（このサイト用のクライアントIDか・メール確認済みか・期限内か）
     │            ③「管理者」シートで有効なアカウントか確かめる → 管理用の合言葉（6時間）を渡す
     │            ④ 以後の操作は、毎回 合言葉と「管理者」シートを確かめてから実行
     ▼
本番DB：「開催日」「ことば」（上演スケジュール）／「管理者」「管理ログ」
```

- 権限：**owner**（すべて＋管理者の追加・停止）／**editor**（上演の登録・変更・中止）／**viewer**（見るだけ）
- 管理者を「停止」にすると、ログイン中の人もその場で使えなくなります。
- 参加者向けの処理（config・boot など）は、ひみつのことばを一切返しません。管理ログにも、ことばそのものは残しません。
- 制作シート（芽美のシナリオ）には触りません。管理サイトが書き込むのは、本番DBの「開催日」「ことば」「管理者」「管理ログ」だけです。

## 2. 本番に入れるときの手順（指示をもらってから行う）

### 2-1. Google Cloud で「ログイン用のクライアントID」を作る（1回だけ）
1. https://console.cloud.google.com/ を開き、プロジェクトを作る（名前の例：`innocent world admin`）
2. 「APIとサービス」→「OAuth 同意画面」：ユーザーの種類「外部」、アプリ名 `innocent world 管理`、サポートメールを入力して保存
   - 公開ステータスは「テスト」のままでよい。その場合は「テストユーザー」に、管理者のGoogleアカウントを追加する
3. 「認証情報」→「認証情報を作成」→「OAuth クライアント ID」→ 種類「**ウェブ アプリケーション**」
   - 承認済みの JavaScript 生成元：`https://satoshikishimoto.github.io`
   - （リダイレクトURIは不要）
4. 表示された **クライアントID**（`……apps.googleusercontent.com`）を控える。※公開してよい値です（パスワードではありません）

### 2-2. サーバー（GAS）に入れる
1. `gas/Code.gs` を貼り替えて保存
2. ⚙ プロジェクトの設定 →「スクリプト プロパティ」に `ADMIN_CLIENT_ID` ＝ 2-1 のクライアントID を追加
3. 関数 **setupAdmin** を1回実行
   - シートの見出しに新しい列が足され、「管理者」「管理ログ」シートができます（中身のデータには触りません）
   - **実行したGoogleアカウント**が owner として登録されます
   - 初回は「外部サービスへの接続」の許可を求められます（Google にログインを確かめてもらうため）。許可してください
4. 「管理者」シートに、管理サイトにログインするGoogleアカウントを確認・追加（例：普段使いのアカウントを owner に）
5. ［デプロイ］→［デプロイを管理］→ 鉛筆 → バージョン「新バージョン」→［デプロイ］（URLは変わりません）

### 2-3. 管理サイトを公開する
- `admin/config.js` の `googleClientId` にクライアントIDを書き、GitHub に反映する

## 3. 上演スケジュールのルール

| 項目 | 内容 |
|---|---|
| 1行＝1上演 | 「開催日」シートの1行が「その日にその作品を公開する」。同じ日に複数の作品を並べてよい |
| 入口のことば | ことばで作品が決まる。同じ日の作品どうしで重ねられない（保存時に止める） |
| 施設のことば | 作品ごとに設定。作品どうしで同じことばでもよい。いま進めている作品のことばだけで判定 |
| 作品の切り替え | 同時に進められるのは1作品。地図の「入口へ」から、別の作品のことばを入れて切りかえる。前の作品の進行は残る |
| 公開時刻 | 開始前は入れない（開始時刻を案内）。終了後は新しい入場を止める |
| 終了後の猶予 | 初期値60分。終了までに入った人は猶予中も続けられる。猶予のあとは操作を受け付けない（届いた記録は残す） |
| 中止 | 行は消さずに「中止」。参加者には表示しない。参加者の記録は残る |
| 日付の変更・削除 | 参加者がいない上演だけ。参加者がいる上演は「中止」にする |
| 進行状況（案A） | 読了・記録・その回で手に入れたアイテムは「作品ID＠開催日」ごと。再公開ははじめから。住民票のアイテム・累計ポイントは通算で残り、ポイントは同じ物語で二重に入らない |
| 古いデータ | ことばの event_id が空の行は「その日の全作品に共通」。作品が1つの日はそのまま動く |

- リハーサル：スクリプトプロパティ `TEST_DATE`（日付）と `TEST_TIME`（例 `10:30`）。設定が残っていると、管理サイトのホームに警告が出ます。
- イベントシートの「公開開始日・公開終了日」は、上演の判定には使わなくなりました（再公開のため。上演は「開催日」シートだけで決まる）。

## 4. 公式サイト向けの開催情報

- action `publicSchedule`：これからの上演（日付・作品名・表示名・公開時刻）を返します。ひみつのことばは含みません。
- 将来の公式サイト（現在のARサイトを発展させたもの）は、これを読んで開催情報を自動で表示できます。
